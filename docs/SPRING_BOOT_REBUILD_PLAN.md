## 1. Current system (what exists today)

Docker Compose (`docker-compose.yml`) runs 5 services:

| Service | What it is | Port |
|---|---|---|
| `db` | Postgres 15, database `trade_db`, user/password `postgres`/`postgres` | 5432 |
| `redis` | Redis 7 | 6379 |
| `backend` | FastAPI (`backend/app/main.py`) | 8000 |
| `worker` | Celery worker (`backend/app/worker.py`), task `process_document(doc_id, file_path)` | — |
| `frontend` | React 18 + Vite dashboard, calls `VITE_API_URL=http://localhost:8000` | 5173 |

Shared volume: `./sample_docs` is mounted at `/data/uploads` in both `backend` and `worker`. The API writes uploaded files there and the worker reads them.

Flow today: `POST /upload` saves the file, inserts a `documents` row (`processed=false`), calls `process_document.delay(doc.id, out_path)`. The worker runs OCR (`ocr.py`), parses fields with Gemini (`nlp.py`), looks up the HS code (`hs_mapper.py`), sets `documents.fields` and `processed=true`, scores risk with the Isolation Forest (`fraud.py`, flag if score > 0.6), inserts a `transactions` row, and appends a hash-chained audit record (`audit.py`, writes `audit_logs` and `backend/models/ledger.txt`).

Tables are created by SQLAlchemy `create_all` in `main.py` (`backend/app/models.py`):

- `documents`: `id` serial PK, `filename` varchar not null (the generated uid, e.g. `3f2a...e1.jpg`), `original_filename` varchar, `fields` json, `uploaded_at` timestamptz default now(), `processed` boolean default false, `processing_notes` text.
- `transactions`: `id` serial PK, `document_id` integer, `invoice_value` double, `hs_code` varchar, `party` varchar, `risk_score` double, `is_flagged` boolean default false, `metadata` json (SQLAlchemy attribute is `meta_info` because `metadata` is reserved there), `created_at` timestamptz default now().
- `audit_logs`: `id` serial PK, `timestamp` timestamptz default now(), `action` varchar, `payload` json, `hash` varchar.

## 2. API contract to preserve exactly

All responses are JSON. CORS must allow any origin, any method and any header (the current API uses `allow_origins=["*"]`).

### `POST /upload`
- Request: `multipart/form-data` with one part named `file`.
- Behaviour: take the extension from the original filename (default `.png` if none), generate `uid = <32 hex chars of a random UUID without dashes> + ext`, save the bytes to `${UPLOAD_DIR}/uid`, insert a `documents` row (`filename=uid`, `original_filename`, `fields={}`, `processed=false`), publish a job (section 4), return:
```json
{"message": "Document uploaded successfully", "document_id": "<uid>", "status": "processing"}
```
Note: `document_id` here is the **uid string**, not the numeric id. The frontend stores it and polls `/status/<uid>`.

### `GET /status/{uid}`
- 404 if no document has `filename = uid`: body `{"detail": "Document not found"}` (same shape FastAPI uses).
- If the document is not processed, or it has no transaction yet: `{"status": "processing"}`.
- Otherwise (`fields` is the document's JSON):
```json
{
  "status": "completed",
  "document_id": 12,
  "transaction_id": 7,
  "invoice_number": "<fields.invoice_no or \"N/A\">",
  "total_amount": "₹12,345.00",
  "gstin": "<fields.gstin or \"N/A\">",
  "party": "<fields.party or \"N/A\">",
  "risk_score": 63.27,
  "is_flagged": true,
  "message": "⚠️ High Risk Transaction"
}
```
  - `document_id` here is the numeric id.
  - `total_amount`: `fields.total_amount` (default 0) formatted as `₹` + thousands separators + 2 decimals. Python: `f"₹{x:,.2f}"`. Java: `String.format(Locale.US, "₹%,.2f", amount)`. If the field is missing, null, or a non-numeric string, treat it as 0 (do not throw).
  - `risk_score`: `transactions.risk_score * 100`, rounded to 2 decimals (`BigDecimal.setScale(2, RoundingMode.HALF_UP)`), returned as a JSON number.
  - `message`: exactly `"⚠️ High Risk Transaction"` if flagged, else `"✅ Safe Transaction"` (UTF-8; make sure the source file and responses are UTF-8).

### `GET /transaction/{id}`
- 404 body `{"detail": "Transaction not found"}`.
- 200:
```json
{"id": 7, "invoice_value": 12345.0, "hs_code": "8471", "party": "ACME", "risk_score": 0.6327, "is_flagged": true, "metadata": {...}}
```
`risk_score` here is the raw 0–1 value. `metadata` is the transaction's JSON or `{}` if null.

### `GET /health`
- `{"status": "ok"}`. (Also enable Spring Boot Actuator `/actuator/health`, but keep `/health` because the frontend calls it.)

## 3. Target architecture

```
React dashboard  --HTTP-->  Spring Boot API (Java 21)  --XADD-->  Redis Stream "logistics:jobs"
                                   |                                        |
                                   | JPA (read/write documents)             | XREADGROUP (group "workers")
                                   v                                        v
                               PostgreSQL  <----- writes results ------  Python worker
                                                                         (OCR, Gemini, HS, Isolation Forest, audit)
```

- **Spring Boot owns the schema** through Flyway migrations. The Python worker never creates or alters tables.
- **The Python worker owns processing.** It reads jobs from the stream and writes `documents.fields/status`, `transactions` and `audit_logs` directly (as it does today).
- **The API only reads results** for `/status` and `/transaction`.

---

## 4. Job message (the contract between Java and Python)

Stream key: `logistics:jobs`. Consumer group: `workers` (created by the worker on start-up with `XGROUP CREATE logistics:jobs workers 0 MKSTREAM`, ignoring the `BUSYGROUP` error if it exists). Use `0`, not `$`: the API may accept uploads before the worker has started, and `$` would skip those jobs forever.

Each job is one stream entry with these string fields:

| Field | Example | Meaning |
|---|---|---|
| `job_id` | `b3c1...` (UUID) | unique id for logs |
| `document_id` | `12` | numeric `documents.id` |
| `file_path` | `/data/uploads/3f2a...e1.jpg` | where the API saved the file |
| `attempt` | `1` | delivery attempt, starts at 1 |
| `enqueued_at` | `2026-11-20T10:15:30Z` | ISO-8601 UTC |

Delivery rules (implemented in the worker, Phase 5):
- On success: `XACK`.
- On failure: if `attempt < 3`, `XADD` a copy with `attempt+1` and `XACK` the original. If `attempt == 3`, set the document's `status='failed'` and `processing_notes=<short error message, no stack trace, no secrets>`, then `XACK`.
- Reclaim stuck entries with `XAUTOCLAIM logistics:jobs workers <consumer> 60000 0-0` on start-up **and on every loop tick where `XREADGROUP` returned nothing** (a worker that crashed and restarted quickly would otherwise leave its entry pending forever).
- **Idempotency:** before processing, if a `transactions` row already exists for `document_id`, just set `status='completed'` and `XACK` (no second transaction, no second ledger line). A retry after a partial failure must never create duplicates.

### Phase 5: Python stream worker (replace Celery)

1. New `backend/app/stream_worker.py`: a loop with `redis.xreadgroup("workers", consumer_name, {"logistics:jobs": ">"}, count=1, block=5000)`, consumer name from `socket.gethostname()`. Reuse the existing processing code: move the body of `process_document` in `worker.py` into a plain function `process(doc_id: int, file_path: str)` and call it from the loop. **Change its error handling:** the current body catches every exception and returns a string (also for "document not found" and "file not found"). `process()` must instead **raise** on any failure (raise a clear exception for missing document/file); only the stream loop catches exceptions and applies the delivery rules from section 4. Also reorder so `processed`/`status='completed'` is committed **in the same transaction as** the `transactions` insert, after scoring, not before it.
2. On success also set `documents.status='completed'`. Update `backend/app/models.py` with the `status` column (no `create_all` anywhere in the worker).
3. Remove Celery from `requirements.txt` and delete `worker.py`'s Celery app once `stream_worker.py` works. Keep `ocr.py`, `nlp.py`, `hs_mapper.py`, `fraud.py`, `audit.py` unchanged.
4. Handle SIGTERM: finish the current job, then exit.
5. `/status` in Java: if `documents.status == 'failed'` return `{"status": "failed", "message": "<processing_notes>"}`. Then in `frontend/src/App.jsx` the polling `useEffect` (it polls `getDocumentStatus` every 2 s and only handles `completed`; it has no timeout): add a branch for `res.status === "failed"` that calls `clearInterval(interval)`, `setStatus("error")` and `setError(res.message || "Processing failed")`. Also stop polling and show an error after 60 attempts (2 minutes) so a lost job cannot spin forever.
6. Tests (`backend/tests/`, pytest): use `fakeredis` or a real Redis from Compose; stub `ocr`, `nlp` and `fraud` with monkeypatch so no Gemini call is made. Test: success path acks and writes a transaction; a failing job is retried with `attempt=2`; the third failure marks the document `failed`.

**Acceptance:** pytest passes; no test calls the real Gemini API.
